# bc250-grub.sh: выбор 6 или 7 ядер в меню GRUB (Fedora / Nobara)

**Языки:** [Português](grub-modos.md) · [English](grub-modos.en.md) · **Русский**

> **В одном предложении:** вместо того чтобы плата сама разблокировала дополнительное ядро при каждой загрузке, теперь **вы выбираете в меню GRUB**, нужно 6 или 7 ядер, а если что-то зависнет, она **сама вернётся к 6 ядрам**. Зацикливания больше нет.

> Сообщения скрипта и названия пунктов GRUB на португальском («nucleos» = ядра, «destrave» = разблокировка, «sem OC» = без разгона, «seguranca» = безопасность). Здесь они приведены точно так, как выглядят на экране.

## Зачем нужен этот скрипт (проблема зацикливания)

В предыдущей версии (этап 5 `bc250-nucleos.sh`) служба разблокировала дополнительное ядро **автоматически при каждой холодной загрузке**:

```
включение → служба пишет 0xFF → тёплый сброс → 7 ядер → (зависание) → снова включение → служба пишет 0xFF → ...
```

Если загрузка с 7 ядрами зависает **после** того, как служба уже отметила её как «OK» (например, из-за разгона или игры), плата зацикливается: при каждом включении она разблокирует ядро и снова зависает.

Хуже того: в Nobara **меню GRUB по умолчанию скрыто** (`GRUB_TIMEOUT=0`). Без меню нельзя было выбрать другой пункт или добавить `bc250.nucleos.nao` в строку ядра. На исходной плате единственным выходом оказалась **переустановка системы**.

## Что изменилось по сравнению с этапом 5 bc250-nucleos.sh

| | Этап 5 (раньше) | `bc250-grub.sh` (теперь) |
|---|---|---|
| Когда разблокирует | При **каждой** холодной загрузке, сам | **Только** когда в GRUB выбран пункт 7 ядер (или с `padrao 7`) |
| Меню GRUB | Скрыто (по умолчанию в Nobara) | **Видно 5 с** при каждой загрузке |
| Если загрузка с 7 ядрами зависла | При следующей загрузке снова разблокирует (зацикливание) | Следующая загрузка **сама возвращается к 6 ядрам** |
| Режим 6 ядер | Только исходный пункт (без ACPI-исправления) | Собственный пункт, **с** ACPI-исправлением и таблицей процессоров, которая **не даёт** запуститься дополнительному ядру |
| Проверка без разгона | Выключать службу разгона вручную | Готовый пункт **«7 ядер без разгона»** |
| Secure Boot включён или таблица процессоров не загрузилась | Продолжал: плохое ядро могло выполнять код при загрузке | **Отменяет** разблокировку до записи маски |
| BIOS обновлена | Использовал таблицу, созданную для старой BIOS | **Отменяет** разблокировку до переустановки |
| Обновление ядра | Пункт пересоздавался только при следующей загрузке | Пересоздаётся сразу (хук `kernel-install`); по умолчанию остаётся 6 ядер |
| ACPI-исправление Control Center установлено позже | Таблицы загружались бы дважды | Обнаруживает это и использует только таблицу процессоров |

`bc250-grub.sh` **заменяет** этап 5. Этапы 1–4 `bc250-nucleos.sh` (проверка каждого скрытого ядра) по-прежнему нужны, чтобы узнать, **какое** ядро исправно. Этот скрипт для случая, когда вы это уже знаете.

## Меню GRUB

После установки меню показывается 5 секунд при каждой загрузке:

```
BC-250: 6 nucleos (normal)              <- по умолчанию. Никогда не разблокирует
BC-250: 7 nucleos (destrave)            <- 7 ядер, с разгоном
BC-250: 7 nucleos sem OC (seguranca)    <- 7 ядер, разгон выключен только на эту загрузку
Nobara Linux (7.2.9-...)                <- исходный пункт системы, не изменяется
```

| Пункт | Ядра | Разгон | ACPI-исправление | Для чего |
|---|---|---|---|---|
| **6 nucleos (normal)** | 6 | вкл. | да | Безопасное использование. Пункт по умолчанию |
| **7 nucleos (destrave)** | 7 | вкл. | да | Обычное использование с дополнительным ядром |
| **7 nucleos sem OC** | 7 | **выкл.** | да | Первая проверка или нестабильный разгон |
| **Nobara Linux** | 6 | вкл. | нет | Последнее средство: загрузка системы без всего из этого проекта |

Выбирайте стрелками и нажимайте Enter. Если ничего не трогать, GRUB загрузит пункт по умолчанию.

## Установка по шагам

Требования: Fedora или Nobara, GRUB с BLS (стандарт для этих систем), загрузка EFI, Secure Boot **выключен**, `/boot` на ext4 или xfs. Скрипт всё это проверяет и **ничего не меняет**, если чего-то не хватает.

1. Скачайте всю папку. Скрипт использует лежащие рядом файлы `bc250-nucleos.sh` и `acpi/`:
   ```
   git clone https://github.com/reinaldovcaetano/bc250-7-core-unlock
   cd bc250-7-core-unlock
   ```
2. (Необязательно) Проверьте плату. Только чтение, ничего не меняет:
   ```
   sudo ./verificar-placa.sh
   ```
   Показывает маску SMU, таблицу процессоров BIOS, пункты GRUB и `grubenv`.
3. Установите:
   ```
   sudo ./bc250-grub.sh instalar
   ```
   Скрипт покажет, что будет создано, и спросит `Instalar agora? [s/N]` («Установить сейчас? [д/Н]»). Ответьте `s` (да).
   - Другое дополнительное ядро (например, 6): `sudo NUCLEOS="6" ./bc250-grub.sh instalar`
   - Повторный запуск безопасен: всё пересоздаётся, выбранный вариант по умолчанию сохраняется. Запускайте в режиме 6 ядер.

Ожидаемый вывод (сокращённо):
```
  OK  mascara 0x77: ocultos = 3 7; liga = 7
  OK  BIOS P3.00: as SSDT do e-tho v1.1.0 (sha256 conferido) vao junto nos dois modos
  OK  menu do GRUB visivel por 5 s
  OK  entradas criadas a partir do kernel 7.2.9-200.nobara.fc44.x86_64
  OK  padrao gravado do GRUB: bc250-6nucleos
  OK  Instalado. Padrao: 6 nucleos.
```

## Первая проверка по шагам

Делайте **по одному шагу** и переходите дальше, только если предыдущий прошёл успешно.

1. **6 ядер.** Перезагрузитесь и дайте GRUB самому выбрать «6 nucleos (normal)». Затем:
   ```
   sudo bc250-grub.sh status
   cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_driver     # ожидается: acpi-cpufreq
   nproc                                                       # ожидается: 12
   ```
   Это подтверждает, что таблица процессоров и исправление энергопотребления загружаются, без какого-либо риска.
2. **7 ядер без разгона.** Перезагрузитесь и выберите «7 nucleos sem OC (seguranca)». Плата загрузится, **сама перезагрузится один раз** (это тёплый сброс) и вернётся. Затем:
   ```
   nproc                                                       # ожидается: 14
   sudo bc250-grub.sh status                                   # "OK: bc250-7nucleos-semoc com 14 threads"
   ```
   Оставьте плату включённой **минимум на 5 минут**. Столько нужно, чтобы загрузка считалась подтверждённой. Нагрузочный тест:
   ```
   sudo dnf install stress-ng
   stress-ng --cpu $(nproc) --cpu-method all --verify -t 15m
   ```
3. **7 ядер с разгоном.** Перезагрузитесь и выберите «7 nucleos (destrave)». Повторите нагрузочный тест.
4. **Сделать 7 ядер вариантом по умолчанию** (необязательно, только когда всё стабильно):
   ```
   sudo bc250-grub.sh padrao 7
   ```

Если на любом шаге зависло: **выключите и включите плату**. Она сама вернётся к 6 ядрам.

После установки команда доступна из любой папки как `sudo bc250-grub.sh`.

| Команда | Что делает |
|---|---|
| `sudo bc250-grub.sh status` | Показывает потоки, маску, текущий пункт, вариант по умолчанию, состояние цикла, `saved_entry`/`next_entry`, последние загрузки и последний сбой |
| `sudo bc250-grub.sh padrao 6` | GRUB сам загружает 6 ядер (исходный вариант по умолчанию) |

## Что происходит, когда вы выбираете «7 ядер»

Оборудование принимает дополнительное ядро только после **тёплого сброса** (перезагрузки без отключения питания). Поэтому каждая загрузка с 7 ядрами превращается в **две загрузки**, вторая автоматическая:

```
1-я загрузка (пункт 7 ядер, заводская маска 0x77, 12 потоков)
   на ~20 с дольше: новая таблица объявляет ядро, которого ещё нет, и ядро Linux его ждёт
   служба: проверяет условия → пишет 0xFF в SMU → отмечает тот же пункт на следующую загрузку → ТЁПЛЫЙ сброс
2-я загрузка (тот же пункт, маска 0xFF, 14 потоков)
   служба: проверяет ядра → "OK" → делает следующую перезагрузку ХОЛОДНОЙ
   после 5 мин работы (или при обычном выключении): "подтверждено"
```

- **Ядра выбирает таблица процессоров (MADT)** из initrd этого пункта. В ней ядро 3 (дефектное) выключено: Linux никогда его не будит.
- **Перезагрузка или выключение** после этого всегда холодные: маска возвращается к заводской 0x77.

## Как работает защита от зацикливания

Три простые идеи, одна поверх другой:

**1. Сохранённый пункт GRUB по умолчанию всегда «6 ядер».**
`saved_entry` в GRUB всегда указывает на `bc250-6nucleos`. Служба восстанавливает это при каждой загрузке, а хук ядра при каждом обновлении (в Fedora есть `UPDATEDEFAULT=yes`, который переключает вариант по умолчанию на новое ядро).

**2. «По умолчанию 7» это билет в один конец.**
С `padrao 7` скрипт использует `next_entry` в GRUB: он действует **одну** загрузку, и **сам GRUB его стирает** перед запуском Linux. Билет обновляется только тогда, когда загрузка с 7 ядрами доказала, что работает:
- проработала **5 минут** (`ESTAVEL="300"` в `/etc/bc250-grub.conf`), **или**
- была **выключена обычным образом** (зависание не является обычным выключением).

Если плата зависнет в любой момент до этого, билет уже израсходован, и следующая загрузка пойдёт на сохранённый пункт: **6 ядер**.

**3. Сбой обнаруживается и записывается.**
Скрипт хранит в `/var/lib/bc250-grub/tentativa`, на каком этапе цикла он находится (`armado`: следующая загрузка запланирована на 7; `destravando`: тёплый сброс выполнен, ждём подтверждения). Если загрузка с 6 ядрами находит этот файл, значит, загрузка с 7 ядрами не завершилась. Тогда скрипт:
- записывает сбой в `boot.log` и `ultima-falha`
- переключает вариант по умолчанию на **6**
- предупреждает в терминале (`wall`) и в `status`

Чтобы снова попробовать 7: выберите пункт в меню или выполните `sudo bc250-grub.sh padrao 7`.

| Сценарий | Что происходит при следующей загрузке |
|---|---|
| Загрузка с 7 ядрами зависла (по умолчанию 6) | 6 ядер; сбой записан |
| Загрузка с 7 ядрами зависла (по умолчанию 7) | 6 ядер (билет уже израсходован); по умолчанию снова 6 |
| Зависание на 1-й загрузке, до запуска службы | 6 ядер; по умолчанию снова 6 |
| Тёплый сброс попал на пункт без новой таблицы (16 потоков) | Служба сразу отключает потоки невыбранных скрытых ядер по APIC ID |
| Выбрали «6 ядер», когда по умолчанию было 7 | Считается сбоем, по умолчанию становится 6 (намеренно осторожно) |

> **Почему `/boot` должен быть на ext4 или xfs?** GRUB может стереть билет (`next_entry`), только если может записать файл `grubenv`, а на btrfs он не пишет. Без этого билет никогда бы не стирался. `instalar` это проверяет.

**А если меню GRUB снова станет скрытым** (например, после обновления Nobara)? Защита продолжает работать, потому что не зависит от того, видите ли вы меню.

## Проверки перед разблокировкой

Перед записью 0xFF в SMU служба проверяет всё перечисленное. Если хоть один пункт не выполнен, она **не разблокирует**, загружается с 6 ядрами и записывает причину в `status`:

| Проверка | Зачем |
|---|---|
| В этой загрузке **используется новая таблица процессоров** с нужными включёнными ядрами (`confere_madt.py`) | Без неё тёплый сброс поднял бы систему с таблицей BIOS, и ядро Linux **разбудило бы плохое ядро** раньше, чем любая служба успела бы его отключить |
| **Lockdown** = `none` (Secure Boot выключен) | При lockdown ядро игнорирует таблицы из initrd |
| **BIOS** та же, что при установке (версия и дата) | В другой BIOS может быть другая таблица процессоров; сгенерированная может не подойти |
| **Маска** равна заводской (0x77) | Странное состояние: лучше отключить плату от розетки |
| `bc250.nucleos.nao` в строке ядра или существует `/etc/bc250-grub.desligado` | Отключено намеренно |

## Обновления

| Что обновилось | Что происходит |
|---|---|
| **Ядро** | Хук пересоздаёт пункты для нового ядра. Если оно пришло **без** `CONFIG_ACPI_TABLE_UPGRADE`, пункты BC-250 удаляются и остаётся пункт Nobara (6 ядер, без ACPI-исправления) |
| **Включён Secure Boot** | Разблокировка отменяется (проверки lockdown и таблицы процессоров) |
| **BIOS** | Разблокировка отменяется до повторного `sudo ./bc250-grub.sh instalar` |
| **ACPI-исправление Control Center** (таблицы в initramfs) | Пункты переходят на cpio только с таблицей процессоров, чтобы таблицы не загружались дважды |
| **GRUB или `/etc/default/grub`** | Если меню снова скроется, защита от зацикливания продолжит работать |
| **Этот проект** (`git pull`) | Снова запустите `sudo ./bc250-grub.sh instalar`, чтобы обновить копию в `/usr/local/lib/bc250-grub/` |

В любом случае худший исход: **загрузка с 6 ядрами**, а причина записана в `sudo bc250-grub.sh status`.

## ACPI-исправление энергопотребления

BIOS P3.00 не сообщает Linux уровни частоты (P-states) и состояния простоя (C-states), поэтому CPU всегда работает на максимальной частоте. Три таблицы из [e-tho/bc250-acpi-fix](https://github.com/e-tho/bc250-acpi-fix) (папка `acpi/`, проверены по sha256) это исправляют:

- **Частотой управляет Linux:** 8 уровней, от **800 до 3200 МГц** (`acpi-cpufreq`).
- **Простой:** ядра засыпают в C1–C3.
- **Разгон (3850 МГц) отдельно:** его применяет SMU через `bc250-smu-oc`. Таблицы не меняют максимальную частоту.

Они включаются в **оба** пункта BC-250 (6 и 7 ядер), только если BIOS версии P3.00 и в initramfs их ещё нет. Исходный пункт Nobara остаётся без них.

**Не устанавливайте дополнительно «ACPI-исправление» из BC250 Control Center**: это те же таблицы. Если всё же установите, скрипт это обнаружит и не загрузит их дважды.

## Разгон

- Служба запускается **до** `bc250-smu-oc`, поэтому разгон применяется только после разблокировки.
- В пункте **«7 ядер без разгона»** службы `bc250-smu-oc`, `cyan-skillfish-governor-smu` и `bc250-cu-live-manager` (те, что есть) маскируются **только на эту загрузку**. Конфигурация не меняется.
- Разгон, откалиброванный на 6 ядрах, может быть нестабилен на 7. Сначала проверьте без разгона, потом при необходимости перекалибруйте в Control Center.

## Что-то пошло не так? Как вернуться

| Ситуация | Что делать |
|---|---|
| Зависло при загрузке с 7 ядрами | Выключите и включите плату. Она сама вернётся к 6 ядрам |
| Нужно 6 ядер прямо сейчас | Выберите в меню «BC-250: 6 nucleos (normal)» |
| Проблема с пунктом 6 ядер от скрипта | Выберите «Nobara Linux (...)», исходный неизменённый пункт |
| Не хочу, чтобы разблокировка происходила вообще | `sudo touch /etc/bc250-grub.desligado` (снова включить: `sudo rm /etc/bc250-grub.desligado`) |
| Отключить только на одну загрузку | В GRUB: клавиша `e` на пункте, добавьте `bc250.nucleos.nao` в конец строки `linux`, затем Ctrl+X |
| Посмотреть, что произошло | `sudo bc250-grub.sh status` и `sudo cat /var/lib/bc250-grub/boot.log` |
| Удалить всё | `sudo bc250-grub.sh desfazer`, затем перезагрузка |

### Измерения под нагрузкой (Nobara, 7 ядер, разгон 3850 МГц / scale −30)

| | Измерено |
|---|---|
| Частота под нагрузкой | **3822–3842 МГц на всех 14 потоках** в течение всего теста |
| Температура (Tctl) | стабильно **~80 °C**, пик **82,2 °C** (предел разгона: 90 °C) |
| Мощность (PPT) | 60–69 Вт |
| Простой сразу после загрузки | Tctl ~45 °C, PPT ~34 Вт; со `schedutil` ядра снижаются до 800–1700 МГц |
| Планировщик | Стандартный планировщик ядра (EEVDF), **без** `scx_lavd`. В отличие от CachyOS, ни одно ядро не застряло на ~1700 МГц под нагрузкой, так что режим Gaming не понадобился |

> **Температура:** примерно на **12 °C выше**, чем в CachyOS (~68 °C), при похожей мощности (различия: scale −30 против −31, температура в комнате и обдув в тот день). Запас до 90 °C ещё есть, но следите за кулером и потоком воздуха, особенно в жару и в тяжёлых играх.

Часть, работающая с оборудованием (SMU, тёплый сброс, таблица процессоров через initrd), та же, что и в `bc250-nucleos.sh`, и ранее проверена в CachyOS с 14 потоками и разгоном 3850 МГц.
